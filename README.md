# Лекция 6. Мобильное приложение на Kivy: трекер доходов и расходов

Учебный проект по дисциплине «Проектирование и разработка бизнес-ориентированного программного обеспечения» (ДВФУ, ШЭМ, направление 38.03.05 «Бизнес-информатика»). Автор: Удовенко Станислав Романович.

Приложение ExpenseTracker из лекции 6 доработано по трём пунктам домашнего задания:

1. добавлены графики (Kivy Garden, matplotlib);
2. реализована синхронизация с облаком (REST API в стиле Firebase Realtime Database);
3. добавлены категории доходов и баланс.

## Возможности

- **Учёт записей.** Каждая запись имеет тип (доход или расход), категорию, описание, сумму и дату. Список записей показывается на главном экране, расходы красным цветом, доходы зелёным.
- **Категории.** Для расходов: Офис, Зарплаты, Маркетинг, Логистика, Налоги, Прочее. Для доходов: Продажи, Услуги, Прочее. При выборе типа записи список категорий меняется.
- **Баланс.** На главном экране выводятся суммарные доходы, суммарные расходы и баланс (доходы минус расходы). Баланс зелёный, пока он не отрицательный, и красный, если расходов больше.
- **Аналитика.** Кнопка «Аналитика» показывает суммы по каждой категории отдельно для доходов и расходов.
- **График.** Кнопка «График» строит столбчатую диаграмму по категориям (matplotlib через `kivy_garden.matplotlib`): доходы зелёные, расходы красные.
- **Экспорт.** Кнопка «Экспорт» сохраняет все записи в файл `expenses_export.csv`.
- **Синхронизация с облаком.** Кнопка «Синхронизация» скачивает записи из облака, добавляет к ним локальные, отправляет объединённый набор обратно и обновляет список на экране.
- **Локальное хранение.** Записи хранятся в файле `expenses.json` (`JsonStore` из Kivy), поэтому приложение работает без интернета.
- **Проверка ввода.** Если не выбрана категория, не заполнены поля или в сумме не число, приложение показывает окно с сообщением об ошибке. Если облако недоступно, выводится сообщение «Нет связи с облаком».

## Установка и запуск

Нужен Python 3.13 (проверено на нём) и Kivy 2.3.2.

```bash
git clone https://github.com/stanislaw584/lecture-6-mobile-app.git
cd lecture-6-mobile-app
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

```

Запуск приложения (скриптом, а не из Jupyter Notebook или интерактивной оболочки):

```bash

```

Без облака приложение работает полностью, кроме кнопки «Синхронизация».

## Облако и синхронизация

Адрес облака задан константой `CLOUD_URL` в начале `main.py`. По умолчанию это тестовый сервер на своём компьютере.

### Тестовое облако

В отдельном окне терминала запустить:

```bash
python server.py
```

Сервер слушает `http://127.0.0.1:8000/expenses.json`. Данные он держит в памяти: после остановки сервера облако пустое.

### Firebase Realtime Database

Формат обмена совпадает с REST API Firebase: один JSON-объект, где ключ это идентификатор записи. Чтобы подключить Firebase, нужно создать базу Realtime Database и заменить адрес в `main.py`:

```python
CLOUD_URL = 'https://<имя-проекта>.firebaseio.com/expenses.json'
```

Правила доступа к базе настраиваются в консоли Firebase. Реальный проект Firebase в репозиторий не подключён.

### Как работает синхронизация

1. Приложение отправляет `GET` на `CLOUD_URL` и получает записи из облака.
2. Локальные записи добавляются к ним по ключу `record_<время в миллисекундах>`. Совпавший ключ перезаписывается локальной версией.
3. Объединённый набор отправляется обратно запросом `PUT`.
4. Те же записи сохраняются в локальный `expenses.json`, список и баланс на экране обновляются.

Удаления записей не синхронизируются: в приложении нет функции удаления.

## Как пользоваться

1. Нажать «Добавить», выбрать тип (расход или доход), категорию, ввести описание и сумму, нажать «Сохранить».
2. Баланс и список обновятся сразу.
3. «Аналитика» показывает суммы по категориям, «График» строит диаграмму.
4. «Экспорт» создаёт `expenses_export.csv` в папке запуска.
5. «Синхронизация» обменивается записями с облаком.
